# Skill routing

Use this guide to choose an installed skill. The owned `sdlc` skill still runs the lifecycle the user asked for. This page only decides which procedure fits the work. Installing or reading a skill does not run it.

The inventory is generated from the real skill set: every package under `skills/` (including Learn subskills), every adopted package under `.agents/skills/`, every skill the installer places from `vendor/`, vendored skills that are intentionally not placed, and any `SKILL.md` under `harnesses/`. `harnesses/skills.json` decides placement. It does not ship a separate skill package today. `python3 skills/sdlc/scripts/routing_inventory.py check` fails when a skill has no routing entry, an entry names a missing skill, or this file's generated region is stale. A vendored `SKILL.md` that redeclares an installed name is an error unless that path is on the duplicate allowlist in `skills/sdlc/scripts/routing_inventory.py`. The allowlist is only Caveman's plugin mirror, Impeccable's per-harness builds, and vendor trees whose installer view is the routed copy.

## Decision guide

Name a skill when the user named it. Otherwise pick the phase, then the stack whose procedure matches.

| Phase | Start here | Use a specialist when |
| --- | --- | --- |
| Discovery / requirements | `sdlc` plan, or `ask-matt` inside Matt's set | The work is an interview (`grill-me`, `grilling`), a spec or tickets (`to-spec`, `to-tickets`, `wayfinder`), a code walkthrough (`how`, `why`), or a brief (`brief`) |
| Design and UI polish | `emil-design-eng`, then `impeccable` or `open-design` | Motion has its own skill (`animate`, `choreograph`, `review-animations`, `animation-performance`). Several live UI variants are `emil-prototype`. One throwaway that answers a design question is Matt's `prototype`. Semantic tokens from Stitch are `design-md`. Generated media is `fal-ai` or the Higgsfield skill the user named |
| Architecture | `architect`, `codebase-design`, or `graphify` | The question is a domain vocabulary (`domain-modeling`), a deepening scan (`improve-codebase-architecture`), or tkstack's own decision rules (`tkstack-principles`) |
| Implementation | `sdlc` for the full loop; `poteto-mode` for Pstack's deep-first default; `implement` for Matt's spec | The win is the smallest diff (`ponytail`), a Swift change (`write-swift`), or a terse voice while some other skill does the work (`caveman`) |
| TDD / clean-code discipline | `ub-mode` for Uncle Bob's make-it-work / make-it-right / practice sequence | The user asked for TDD by name: Pstack's `tdd` keeps that name. Inside Matt's workflows use `matt-tdd`. Pstack's `principle-*` skills and `ponytail` cover subtraction, boundaries, and idempotence without switching stacks. Upstream `ub-mode` Practice says to commit often and push to the main line. That conflicts with stacked PRs and commit-only-when-asked; do not follow that push step |
| Review | `unslop` for cross-artifact slop; `code-review` for a diff against a spec | Prose-only Pstack rules are `pstack-unslop`. Code cleanup is `deslop`. Motion craft is `review-animations`. Adversarial or multi-model passes are `interrogate`, `council`, and `cross-model-review`. Strict maintainability is `thermo-nuclear-code-quality-review` |
| Debugging | `investigate` or `diagnosing-bugs` | Reproduce before editing (`investigate-first`). No narrower playbook fits (`figure-it-out`). A check is red (`fix-ci`). The interface needs a local harness (`control-ui`, `control-cli`) |
| Docs | `document` for the repo; `write` for a human-facing draft | A repository wiki through its real lifecycle is `openwiki`. Agent-facing docs are `writing-for-agents`. A session handoff is `handoff` |
| Release / ops | `file-pr` and `babysit-pr` | `full-stop` reaches the human merge gate. `full-send` merges only when explicitly requested. CI loops, conflict fixes, and smoke tests are Cursor Team Kit. Lever's `pr-shepherd` and `landing-plan` coordinate an already-open set of PRs |
| Learning | `learn`, then the matching `/learn` subskill | A measured improvement loop is `hill-climb`. A repeated correction should become one durable layer (`steer-once`). A transcript retrospective is `reflect` or `retro`. WikiSkill and `skillopt-sleep` are the pinned evolution experiments, not replacements for `learn` |

## Aliases and placement

Three names collide. The installer keeps the preferred skill's name and rewrites the other in a generated view. Pinned bytes under `vendor/` stay unchanged.

| Installed name | Keeps the name | Aliased skill |
| --- | --- | --- |
| `tdd` | Pstack | Matt's TDD skill is `matt-tdd`, and Matt's callers are rewritten |
| `unslop` | Personal `unslop` | Pstack's prose skill is `pstack-unslop`. Pstack's other callers still say `unslop` on purpose |
| `prototype` | Matt's throwaway prototype | Emil's UI variant picker is `emil-prototype`. Emil's quoted call in `break-ui` is rewritten in the generated view |

Skills under `skills/` join every selected harness. Learn subskills are not separate installs. Harness-independent upstream skills, including Emil Kowalski, ub-mode, and the adopted packages, follow `placement.default`: Codex (`.agents/skills`), Grok, Kimi, OpenCode, GitHub Copilot (`~/.copilot/skills` or `.github/skills`), and Muse (`~/.config/muse/skills`, or `.agents/skills` in a project) when those harnesses are selected. The Muse home link does not follow `XDG_CONFIG_HOME`. The default install selects Codex, Claude Code, and Cursor, so that set lands in the shared Codex directory unless you pass `--harness`. Pstack and Cursor Team Kit are Cursor-only. Graphify and Impeccable keep Codex, Claude Code, and Cursor. t3code has no skills directory of its own. `harnesses/skills.json` `delegates.t3code` names the hosts it runs, and the same file is the placement record.
