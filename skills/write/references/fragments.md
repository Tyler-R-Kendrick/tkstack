# Collect fragments

Use this branch when the user wants to explore rather than commit to an outline.
A fragment is a possible sentence, observation, example, objection, question,
quote, or unfinished thought. Record it with enough context for the author to
recognize its meaning. Do not force an article structure onto the collection.

Use the requested file, or the project's existing draft location. Keep a single
working title and separate fragments clearly. Preserve exact quoted wording
and its real source. Label assistant-generated examples as examples instead of
attributing them to the user.

Re-read before appending. User edits, cuts, and reordering take precedence over
the remembered version. Editing a specific fragment does not authorize replacing
the collection. A source that changes while it is being read needs reconciliation
before writing over it.

For a collaborative session, ask a concrete question that unlocks missing
material. For a supplied complete brief, use what is available and continue.
The collection is done when it has enough useful material for the requested
next step, not when it reaches a word count. Shaping produces a separate draft.
