# Headroom runtime and context fidelity

Use the installed Headroom runtime or an explicitly selected executable. In the
tkstack checkout, `scripts/tool.py headroom` launches the pinned runtime recipe
and `scripts/setup_integrations.py --status` reports readiness. A standalone
skill does not supply those scripts or the Python package.

For explicitly requested proxy use, bind locally and follow the actual runtime's
supported configuration. Keep originals available for reversible retrieval and
retrieve exact context when errors, identifiers, command quoting, requirements,
or evidence depend on it. Sample real compressed and recovered material before
claiming fidelity. Compression must not silently remove task obligations.

Preserve active account/provider routing. Wrapping and unwrapping are explicit
operations with the runtime's real recovery procedure. Do not stack another
proxy or rewrite API destinations as an incidental context optimization.

Distinguish retained context, output bytes, token estimates, served model usage,
and actual billing. Measure the quantity claimed using comparable workloads.
An unavailable runtime or inaccessible original remains a concrete limitation.
