# Turn learning into a durable mechanism

Capture an explicit correction immediately with its actual provenance. Repeated
occurrences strengthen evidence; they are not a prerequisite for honoring the
user. A tool trace, source skill, or assistant inference is procedural evidence,
not user authority. Keep uncertain interpretations outside active steering.

After identifying the mistaken decision, choose the smallest effective layer:

| Failure | Durable owner |
| --- | --- |
| Missed factual invariant | Type, parser, contract, linter, or CI check |
| Mechanically detectable tool boundary | Native permission or a precise hook |
| Reusable sequence | Existing skill, with conditional references |
| Stable scoped working context | Canonical instructions |
| Reasoning preference | Evidence-backed scoped steering rule |
| Runtime launch or scheduler defect | A runtime correction, not stronger prose |

Use `instructify`, `reusify`, `skillify`, `codify`, `flowify`, `lintify`, or
`hookify` as selected by the actual mechanism. See
[session consolidation](session-consolidation.md) for scoped evidence, abstract
reasoning, deterministic routing, and verified execution. Do not copy the raw feedback into every package. Prefer one
canonical mechanism with a clear trigger and meaningful exceptions.

If evaluating recurrence, define the observation window, opportunity denominator,
and comparable task mix before reporting rates. Zero observed corrections in
an unavailable transcript is missing evidence. No generic reduction percentage
or minimum message count establishes success across users.

For a retrospective, distinguish repeated mechanisms, successful transferable
procedures, temporary facts, and untested hypotheses. Preserve failed attempts
so the next session does not repeat them. Inspect only authorized history.
Direct requested feature changes use appropriate engineering validation;
automatic revision search retains SkillOpt's held-out strict/no-regression gates.
