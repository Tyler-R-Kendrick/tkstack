# Design scoped context

Separate stable context from a procedure the agent must run. Point to the
canonical vocabulary, policy, or workflow and state the exact condition that
requires it. Keep frequently loaded instructions short; move branch-specific
detail into linked Markdown. A weak selector is a routing problem, not a reason
to duplicate the whole document everywhere.

An instruction identifies trigger, action, verification, boundary, and source.
Use concrete verbs and supported commands. Keep alternatives distinguishable:
"For a captured runtime trace, read the diagnosis reference" is stronger than
"be thorough with debugging." Avoid an unconditional provider-specific command
in guidance intended for several harnesses.

Inspect inheritance, directory scope, file globs, imports, and existing owners
before writing. Root instructions affect many tasks; nested files should add
only local facts. Preserve native imports and owner-marked content. A copied
package or an instruction pointer does not establish that a host loaded it.

Keep user correction history in `learn`, procedures in skills, and mechanical
invariants in their real enforcement layer. Instructions explain the owner;
they do not acquire precedence by being repeated or grant tool permissions.
Test the rendered preview against representative paths and verify actual
native loading when claiming it. Content checks cannot prove model compliance.
