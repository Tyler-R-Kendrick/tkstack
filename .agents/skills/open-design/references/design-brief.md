# Brief and visual direction

Resolve the user's objective, audience, platform, content, incumbent visual
identity, constraints, and requested scope. Inspect the actual project and any
supplied references before inventing a direction. Missing design documentation
does not make a mature interface a blank canvas.

Classify the surface by the visitor's task: make a decision, operate a tool,
read/understand, or experience the work itself. A marketing page and the same
product's settings screen can need different expressive intensity. State the
reason for the chosen direction in terms of that task.

Refinement preserves identity, behavior, and facts outside scope. Redesign may
replace visual language while preserving product truth, function, and required
affordances. Do not invent claims, testimonials, integrations, pricing, or logos
to make a composition look complete.

Choose a coherent hierarchy, type, spacing, color, image, and motion language.
Explore meaningfully different directions only for a real unresolved choice.
Use real supplied imagery when needed; do not generate decorative assets or
spend provider credits without the task's existing authorization.

Before editing, select the actual renderer and evidence path. If a runtime is
unavailable, existing fresh captures can ground a bounded design review; label
unobserved runtime behavior explicitly. A source-only plan is not visual proof.
