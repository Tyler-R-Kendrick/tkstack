# OpenDesign adapter

When OpenDesign is explicitly selected, discover its real MCP tools and runtime
readiness. In the tkstack checkout, `scripts/setup_integrations.py --status` and
`scripts/tool.py open-design` provide local integration entrypoints. A standalone
skill does not contain that checkout or install the application. Never invoke
the unrelated system byte-dump `od` utility.

Use Open Design Cloud by default within this provider; use Local Codex or secure
BYOK when the user selected it. Preserve that selection. A failed account does
not authorize another provider or billing path.

Use the established brief and any server-issued workflow context. Satisfy the
server's actual required confirmation within the task's existing authorization;
do not introduce a separate generic approval ritual. Submit once, retain request
IDs, and poll that run to its actual terminal result. Return the exact Studio or
preview URL. A failed or unknown result is not a completed design.

Generic design requests can use another available authorized renderer. Keep the
portable brief/craft/system procedure, and report what that renderer actually
executed. Explicit OpenDesign requests remain with this provider or blocked.
